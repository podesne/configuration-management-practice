# Эмулятор оболочки

Практическая работа № 1 по предмету «Конфигурационное управление».
Группа ИКБО-62-25, вариант 17. Сейчас готов первый этап.

Программа читает команду в терминале, разбирает аргументы и печатает
результат. Такой цикл называется REPL. Приглашение содержит имя
пользователя и имя компьютера из ОС, например `student@laptop:~$`.

Команды `ls` и `cd` пока работают как заглушки: выводят своё имя и список
аргументов. `cd` оставляет текущую папку без изменений. Знак `~` в
приглашении на этом этапе обозначает начальное положение.

## Запуск

Нужен Python 3.10 или новее. Сторонних библиотек нет, отдельная сборка
не требуется. Откройте терминал в папке проекта.

На macOS и Linux:

```sh
sh run.sh
```

Можно запустить через интерпретатор напрямую:

```sh
python3 -m src.main
```

На Windows:

```bat
run.bat
```

Или:

```bat
python -m src.main
```

Скрипт `run.sh` по умолчанию вызывает `python3`. Переменная окружения
`PYTHON` позволяет указать другой интерпретатор.

```sh
PYTHON=/path/to/python sh run.sh
```

Параметры VFS и стартового скрипта появятся на втором этапе. VFS означает
виртуальную файловую систему: файлы и папки, с которыми работает эмулятор.

## Команды и разбор ввода

| Команда | Поведение на первом этапе |
| --- | --- |
| `ls` | Печатает `ls` и все переданные аргументы |
| `cd` | Печатает `cd` и все переданные аргументы |
| `exit` | Завершает программу; аргументы запрещены |

Обе заглушки принимают любое число аргументов. Проверка путей и
поддерживаемых флагов относится к этапу с настоящей логикой команд.

Парсер, то есть обработчик строки ввода, понимает следующие правила.

- Пробелы и табуляция разделяют слова. Пустой ввод возвращает приглашение.
- `$HOME` и `${HOME}` раскрываются через окружение реальной ОС.
- Неизвестная переменная даёт пустую строку.
- Двойные кавычки сохраняют пробелы внутри аргумента и разрешают подстановку.
- Одинарные кавычки сохраняют текст буквально, включая знак доллара.
- Обратная косая черта экранирует следующий символ вне кавычек.
- В двойных кавычках она экранирует доллар, кавычку и саму косую черту.
  Перед прочими символами косая черта сохраняется.
- Соседние части без пробелов образуют одно слово, например `a"b c"`.

Значение переменной сохраняется одним аргументом, даже если в нём есть
пробелы. Повторная подстановка в полученном значении не происходит.
Это выбранное правило прототипа: полную грамматику Bash он не повторяет.
Конвейеры, перенаправление вывода и запуск программ ОС не поддерживаются.

Незакрытая кавычка, незавершённое экранирование, неизвестная команда и
аргументы у `exit` дают сообщение об ошибке. После этого можно ввести
следующую команду. `Ctrl+C` возвращает приглашение, конец ввода завершает
программу. На macOS и Linux конец ввода можно передать через `Ctrl+D`,
на Windows через `Ctrl+Z` и Enter.

## Пример диалога

Ниже условные имя пользователя, имя компьютера и значение `HOME`.
При запуске программа возьмёт их из вашей ОС.

```text
student@laptop:~$ ls
ls: []
student@laptop:~$ ls -a "my folder"
ls: ['-a', 'my folder']
student@laptop:~$ cd $HOME
cd: ['/home/student']
student@laptop:~$ ls ${HOME}/docs
ls: ['/home/student/docs']
student@laptop:~$ ls '$HOME' ""
ls: ['$HOME', '']
student@laptop:~$ ls \$HOME
ls: ['$HOME']
student@laptop:~$ unknown
Ошибка: Неизвестная команда: unknown
student@laptop:~$ ls "folder
Ошибка: Незакрытая кавычка или незавершённое экранирование
student@laptop:~$ exit now
Ошибка: Команда exit не принимает аргументы
student@laptop:~$ ls
ls: []
student@laptop:~$ exit
```

Для очной защиты запустите программу и повторите эти команды. Дополнительно
проверьте пустую строку, одинарные и двойные кавычки с `$HOME`, переменную,
которой нет в окружении, и обратную косую черту в конце строки.
Попробуйте `Ctrl+C`, затем снова выполните `ls` и завершите программу.

## Тесты

Из папки проекта на macOS и Linux:

```sh
python3 -m unittest discover -s tests -v
```

На Windows:

```bat
python -m unittest discover -s tests -v
```

Тесты проверяют подстановку переменных, границы аргументов, кавычки,
приглашение из данных ОС и поведение команд. Есть проверки продолжения
диалога после ошибок, конца ввода и `Ctrl+C`.

## Файлы и функции

| Файл | Содержимое |
| --- | --- |
| `src/parser.py` | Разбор строки и подстановка переменных |
| `src/shell.py` | Приглашение, заглушки и цикл ввода |
| `src/main.py` | Точка входа в программу |
| `tests/test_parser.py` | Тесты обработки ввода |
| `tests/test_shell.py` | Тесты команд и диалога |
| `run.sh`, `run.bat` | Запуск из папки проекта |
| `.gitignore` | Исключения для кеша, сборок и настроек редактора |

Функции описаны в строках документации внутри кода.

| Функция | Назначение |
| --- | --- |
| `parse_command(line, environment)` | Возвращает имя команды и аргументы |
| `expand_word(word, environment)` | Собирает слово из частей в кавычках и без них |
| `expand_text(text, environment, quoted)` | Раскрывает переменные и экранирование |
| `replace(match)` внутри `expand_text` | Обрабатывает одну найденную подстановку |
| `build_prompt()` | Получает пользователя и имя компьютера для приглашения |
| `execute_command(words, write)` | Выполняет заглушку либо обрабатывает `exit` |
| `run_repl()` | Читает ввод и выводит ошибки до завершения диалога |
| `main()` | Запускает `run_repl()` |

У `parse_command` окружение по умолчанию берётся из `os.environ`.
В тестах можно передать свой словарь. У `execute_command` функция вывода
по умолчанию `print`; тесты заменяют её для проверки результата.

## Как связаны этапы варианта 17

Требования взяты со страниц 56-58 сборника «ИКБО-62-25» за 2026 год.

| Этап | Что появляется |
| --- | --- |
| 1. REPL | Консоль, приглашение из ОС, переменные, заглушки `ls` и `cd`, `exit` |
| 2. Конфигурация | Путь к VFS, своё приглашение, стартовый скрипт с комментариями `#`, вывод параметров и скрипты проверки |
| 3. VFS | Чтение ZIP-файла в память, представление двоичных данных, проверки разных деревьев файлов |
| 4. Основные команды | Настоящие `ls` и `cd`, команды `tail`, `uniq`, `head` |
| 5. Дополнительные команды | Копирование командой `cp` в памяти |

По этому порядку заглушки сохраняются до четвёртого этапа. Тогда их вывод
заменяет работа с VFS. На втором этапе пользовательское приглашение может
переопределять приглашение из ОС; без настройки остаётся прежнее.
Это способ совместить требования, поскольку методичка не описывает
приоритет приглашений отдельно.

Ещё одна неоднозначность касается ZIP-файлов. VFS на третьем этапе должна
загружаться из ZIP, но общие правила запрещают архивы в репозитории.
Тестовые архивы можно создавать скриптом перед проверкой и исключать из Git.
Обычные команды будут менять только состояние в памяти.

Каждый этап сохраняется отдельным коммитом. В сообщении указывается
тип изменения и область, например `feat(stage1): ...`.
Последующие этапы продолжают тот же проект; история Git сохраняет
предыдущие версии для просмотра и защиты.
